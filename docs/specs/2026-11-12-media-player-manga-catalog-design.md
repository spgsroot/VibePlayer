# Медиаплеер: каталог и ридер

Дата: 2026-11-12. Источник фильтров: [NHApp](https://github.com/e18lab/NHApp) (`buildV2Query`, `SortContext`, `TagFilterContext`, `DateRangeContext`, `blacklistFilter`). Существующий ридер описан в `docs/plans/2026-11-12-nhentai-reader.md`.

## Зачем

Peachy — медиаплеер. Главная фича — Buttplug. Видео и манга — два режима одного приложения, не два разных продукта. Сейчас манга — горизонтальный пейджер без памяти страницы и поиск с зашитой сортировкой `date`. Нужен каталог с фильтрами NHApp и ридер, которым удобно читать, не теряя импульс на перелистывание.

## Что решил пользователь

- Каталог нужен, с теми же фильтрами, что в NHApp.
- Приложение остаётся медиаплеером: видео и манга, ось — Buttplug.
- Из NHApp берётся механика ридера и каталога, не чужой стек.

## Цели

- Главный экран по-прежнему видеоплеер. Манга открывается с него и возвращает на него.
- Каталог ищет `https://nhentai.net/api/v2/search` и умеет те же фильтры, что NHApp собирает в query и `sort`.
- Ридер продолжает с последней страницы, прячет хром, листает страницами и вертикальной лентой, зумит, показывает миниатюры и шлёт импульс Buttplug на смену страницы.
- Сохранённая библиотека, избранное и скачивание страниц в `files/manga/{id}/` остаются. Ключ по-прежнему только в заголовке `Authorization`.

## Не цели

- Поиск по картинке. У NHApp это отдельный сервер, не nhentai.
- Аккаунт nhentai, комментарии, персонажи, рекомендации, облако и экран онлайн-избранного. Уже существующий `POST`/`DELETE` избранного при нажатии сердца остаётся. Онлайн-чёрный список не читается.
- Двойной разворот. В NHApp он только на планшете в ландшафте. Это приложение телефонное.
- Бесконечная лента каталога. Результаты идут страницами API.
- Перенос React Native и WebView вместо каталога. Ридер и каталог — Jetpack Compose, не страница nhentai внутри WebView. Существующий WebView видео-источников не трогается.

## Антицели

- Манга становится стартовым экраном, а плеер прячется.
- Ползунок силы хаптики снова висит поверх каждой страницы.
- Фильтры живут только как сырой текст, который пользователь должен помнить.

## Ограничения

- Kotlin, Jetpack Compose, Room, существующий `NhentaiApi`. Новый клиент не заводится.
- Сортировка — query-параметр `sort`, не часть строки поиска. Допустимые значения: `date`, `popular`, `popular-today`, `popular-week`, `popular-month`.
- Картинки только с `https://i1.nhentai.net` и `https://t1.nhentai.net`.
- `files/manga/` не попадает в backup и device transfer.
- Тема окна тёмная. Навигация без fade.

## Фильтры каталога

Один набор на поиск и выдачу. Сброс очищает теги, дату, страницы и чёрный список не трогает.

Строку запроса собирает чистая функция. Пробел между частями. Пустой запрос допустим.

- Текст пользователя идёт как есть, обрезанный по краям.
- Включить тег: `type:name`. Имя с пробелом в двойных кавычках.
- Исключить тег: `-type:name`. Цикл на одном теге: нет → включить → исключить → нет.
- Типы: `language`, `tag`, `artist`, `character`, `parody`, `group`, `category`.
- Языки-чипы — те же include-теги: `english`, `japanese`, `chinese`, `translated`.
- Дата-пресеты, как есть в query NHApp: `uploaded:>2h`, `uploaded:>24h`, `uploaded:>3d`, `uploaded:>7d`, `uploaded:>30d`, `uploaded:>90d`, `uploaded:>180d`, `uploaded:>1y`. Свой диапазон: `uploaded:>YYYY-MM-DD uploaded:<YYYY-MM-DD`, конец не включая.
- Страницы: `pages:N`, `pages:>N`, `pages:<N`, вместе `pages:>N pages:<M`. Ноль и отрицательные не попадают в запрос.
- Числовой запрос из одних цифр открывает галерею, а не поиск.
- История запросов — 10 последних, без дублей, новые сверху.
- Чёрный список локальный и про теги, не про название галереи. Совпадение по id тега или по имени тега в нижнем регистре, точное. Карточка поиска скрывается, если среди `tag_ids` есть заблокированный id. Имя применяется, когда имена тегов уже известны.

## Ридер

Маршрут `manga/{id}` остаётся ридером. Каталог открывает его.

- Старт со страницы из истории чтения, если она есть и меньше числа страниц. Иначе с первой.
- Режимы: постраничный горизонтальный и вертикальная лента. Жест запоминается.
- Тап по левой трети листает назад, по правой вперёд, по центру показывает или прячет хром. Зеркало для левой руки запоминается.
- Щипок увеличивает страницу. Двойной тап возвращает масштаб 1.
- Миниатюры текущей галереи, тап прыгает на страницу.
- Вписывание: целиком или по ширине. Запоминается.
- Хром прячется. Сила импульса живёт в листе настроек ридера, не на странице.
- Вертикальная лента: текущая страница — та, чья середина ближе всего к центру видимой области. Импульс и запись истории только когда прокрутка простаивает и эта страница сменилась. Первая установка позиции импульс не шлёт. Бросок не шлёт импульс на каждую пересечённую страницу.
- Смена страницы в постраничном режиме, кроме первой установки позиции, тоже зовёт существующий `PageTurnHaptic`.
- Уход с экрана пишет ту же историю для текущей страницы, даже если прокрутка ещё не простаивала.

## Оболочка

Стартовый маршрут — `player`. Иконка библиотеки открывает хаб манги с тремя вкладками: Каталог, Библиотека, История. Галерея видео остаётся галереей видео. Назад из хаба возвращает на плеер.

Карточка каталога: обложка, название, число страниц. Тап открывает ридер. Сохранение и избранное — те же действия, что уже есть у библиотеки.

## Данные

Миграция Room 5 → 6.

- `read_history`: `galleryId` PK, `title`, `thumbnailPath`, `page`, `pageCount`, `readAt`.
- `search_history`: `query` PK, `usedAt`. Хранится не больше 10 строк.
- `tag_blacklist`: `kind` (`id` или `name`), `value`, уникальная пара. `value` для имени уже в нижнем регистре.

Прогресс чтения не дублируется в `library_galleries`. Настройки ридера (режим, вписывание, зеркало тапов, сила) — SharedPreferences, не колонки `settings`.

## Что оставлено строителю

- Точные имена Compose-экранов и строк ресурсов, если сигнатуры из плана соблюдены.
- Календарь своего диапазона: два поля даты, не копия их сетки месяца.
- Превью миниатюр грузятся лениво, соседние страницы ридера — тоже. Число соседних страниц выбирает строитель, не меньше одной вперёд.
